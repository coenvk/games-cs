# Paddock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Paddock, a pixel-art car collecting and racing game (desktop and browser) in games-cs, with the
general parts it needs added to the Jentl engine.

**Architecture:** Four layers, built in this order. (1) Engine (`../jentl`, repo coenvk/jentl-cs): two new
framework-free packages, `Jentl.Collect` (weighted draws, recharging counters, date rotations) and `Jentl.Tracks`
(track paths from straights and arcs), a pixel canvas in `Jentl.Assets`, and a road painter and heading-following
camera in `Jentl.Core`; released as Jentl 0.2.0. (2) Rules: framework-free `src/Paddock` with xUnit tests: cars,
tracks, the race simulation, upgrades, matches, economy, events, campaign. (3) Art: `tools/CarArt` draws every car
in code into an atlas. (4) App: `apps/Paddock` on `shell/`, like the other games.

**Tech Stack:** C# 14 / .NET 10, MonoGame DesktopGL 3.8.4.1, KNI 4.3.9001 (BlazorGL), xUnit + FluentAssertions 6.12.0,
System.Numerics, System.Text.Json (source-generated contexts, as in the other games), `TimeProvider` for clocks.

**Spec:** `docs/superpowers/specs/2026-10-24-paddock-design.md` (mockups in `docs/superpowers/specs/paddock-mockups/`).
Read both; the plan argues from the spec.

## Global Constraints

- Everything invented: no real car names, makers, logos or look-alike designs.
- No real money, ads, gold or premium currency; one currency: **cash**. No server, no online play.
- **Engine rule (owner):** anything Jentl lacks that Paddock needs goes into Jentl (`../jentl`), not into Paddock.
- Rarity classes **F, E, D, C, B, A, S**; hand of **five** cars under an **RQ limit**; **RQ never changes with upgrades**.
- Upgrades: **three stages**; per stage **8 points, at most 3 per area** (engine, weight, chassis); a full stage
  needs a **fuse** of another car of the **same rarity class**, which is consumed; tune cumulative, shown "E.W.C"
  (e.g. "3.3.2", fully upgraded e.g. "9.9.6"); tune reset keeps the stage.
- Match: five rounds; player sees tracks, conditions and the opponent's five cars, then orders their own five; most
  rounds won wins, tie broken by larger total winning margin; a round never draws.
- Results deterministic: same inputs, same results, desktop and browser alike. The race simulation uses no
  trigonometry (`Math.Sqrt`, `Math.Log` and arithmetic only), so results are bit-identical across platforms.
- Events: 2-3 at once, fixed calendar from the date (UTC), ladder of ~12 matches, **5 tickets, one back every 30
  minutes**, a race costs a ticket win or lose, recharge also while closed. Campaign unlimited.
- Race view: circuits top-down close-up following the player's car, mini-map, gap, weather; drags side view; round
  playback 10-20 s (drags 6-8 s); **skip button**; option **Race camera: Fixed (default) / Turn with car**.
- Full card look (mockup `car-card.html`, style A). English and Dutch (`shell/Assets/lang/nl.json`).
- Repo rules: TreatWarningsAsErrors, analyzers, files UTF-8 with BOM and LF; run `dotnet format whitespace` before
  each commit. Commits: no `Co-Authored-By` or "Generated with" lines.
- Pushing: ask the owner before the first push of each repo in this plan and before pushing the `v0.2.0` tag.

## Review Focus

1. **Clock changes** (system clock set back, or weeks closed): tickets never go below 0 or above 5, never go
   negative-time, and a clock set back does not grant tickets. Test in Task 1 (`RechargingCounter`).
2. **Saves that no longer match the game** (car id removed from the roster, corrupt JSON, older save without new
   fields): load skips unknown cars, keeps the rest, never crashes. Test in Task 11.
3. **Fewer than five eligible cars** (new garage, strict event rules): the event and hand screens say why and don't
   start; the starter garage always has at least 5 cars that fit level 1's RQ limit. Tests in Tasks 10, 11 and 12.
4. **Fusing a car into itself, or a car of another class, or a car in no stage-full state**: rejected, nothing
   consumed. Test in Task 8.
5. **Playback disagreeing with the result** (time compression or rounding letting the loser cross first): the loser
   is never ahead at the finish in the played trace. Test in Task 7 (`RaceRun.DistanceAt`) and Task 19.

### Task 7: The race simulation

**Files:** Create `src/Paddock/Tracks.cs`, `src/Paddock/RaceSimulator.cs`, `src/Paddock/Balance.cs`,
`apps/Paddock/Assets/paddock/tracks.json`; Test `tests/Paddock.Tests/RaceSimulatorTests.cs`

**Interfaces:**
- Consumes: `Stats`, `Condition`, `Tyres`, `Drive`, `Clearance` (Task 6); `PathSegment`, `TrackPath` (Task 2).
- Produces:
  - `public enum TrackKind { Drag, Circuit, Twisty, City, HillClimb, OffRoad }`.
  - `public sealed record TrackDef(string Id, string Name, TrackKind Kind, IReadOnlyList<TrackPiece> Pieces, IReadOnlyList<Condition> Conditions)`
    with `public sealed record TrackPiece(double Length, double Radius = 0, double Degrees = 0, double Gradient = 0)`
    (radius 0 = straight; gradient as rise/run) and `TrackPath ToPath()`; `static IReadOnlyList<TrackDef> TrackDef.ListFromJson(string)`.
  - `public sealed record RaceRun(double Time, IReadOnlyList<double> TimeAtMetre)` with `double DistanceAt(double time)`
    (monotonic interpolation; 0 before start, total length after `Time`).
  - `public static class RaceSimulator`: `RaceRun Run(Stats stats, TrackDef track, Condition condition)`.
- Algorithm (pinned; numbers go in `Balance`, these are the starting values):
  - `vmax = TopSpeedKmh / 3.6`, scaled by clearance on rough conditions (Dirt, Gravel, Sand, Snow): Low ×0.80, Mid ×0.93, High ×1.
  - Grip `μ = (0.6 + 0.6 × Handling/100) × TyreGrip[tyres, condition]`, with `TyreGrip` (Dry, Wet, Dirt, Gravel, Snow, Ice, Sand):
    Slick 1.10 .55 .45 .45 .30 .15 .35; Performance 1.00 .75 .55 .55 .40 .20 .40; Standard .90 .80 .65 .65 .50 .25 .50;
    AllSurface .85 .80 .80 .80 .65 .35 .65; OffRoad .75 .70 .90 .90 .75 .40 .85.
  - Engine acceleration `a(v) = A × (1 − v/vmax)` with `A = −(vmax / ZeroTo100) × ln(1 − 27.78/vmax)` (so 0-100 matches
    the stat), capped by traction `μ × 9.81 × DriveShare` (Fwd 0.60, Rwd 0.65, Awd 1.0), minus `9.81 × Gradient`.
  - Corner limit `v ≤ sqrt(μ × 9.81 × radius)`; braking `μ × 9.81 × 0.9`.
  - Integrate per metre: speed limits per metre, forward pass `v[i+1] = sqrt(v[i]² + 2·a(v[i])·1)` capped by the limit,
    backward pass for braking, `TimeAtMetre[i+1] = TimeAtMetre[i] + 2 / (v[i] + v[i+1])`. Standing start; `Math.Sqrt`
    and `Math.Log` only.
